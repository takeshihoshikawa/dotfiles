# course-grading — 採点データとルーブリックのリファレンス

手順は **course-qa**（ミニットペーパー取り込み＋履修態度採点＋QA）・**course-exam**（試験採点）・
**course-review**（振り返り）が担う。ここは3つが共有する規約の正本で、
**各スキルはここを参照し、規約を再掲しない**（再掲すると必ず片方が腐る）。

## ファイル配置

素点データは**教材フォルダに置く。git 管理外**。学生の点数をリポジトリに入れないための分担で、
コードだけが `~/work/projects/admin/` に入る。

```
~/Documents/lecture/{lecture_dir}/assessment/{年}{クラス種別1文字}/
├── scores_exam.csv                試験の設問別素点
├── scores_report.csv              レポート・演習の素点
├── scores_attitude.csv            履修態度（ミニットペーパー）の素点
├── scores_attitude_reference.csv  規準を学生に示す前に採点した参考値（成績に使わない）
├── grading_config.json            Teams 入力欄の満点と、換算の流儀
├── grading_policy_{年}{クラス}.md  採点基準・判断事例・次回への申し送り
├── {YYYYMMDD}_minute_papers.pdf   ミニットペーパーのスキャン（回収日）
├── {YYYYMMDD}_answers.pdf         答案のスキャン
└── course_evaluation.pdf          授業評価アンケート
```

- `lecture_dir` は vault の `courses/{course_id}/_meta.md`。無ければ `courses/registry.md` の表
- **開講フォルダはクラス種別1文字**（U2 → `2026U`、J1 → `2026J`）。既存の `2024J`/`2025U` に合わせる
- 試験問題・解答例（`試験問題.docx`・`試験解答.txt` 等）は**先生が作る文書なので日本語名のまま**。
  パターンで探す

## CSV の規約

- **先頭列は学籍番号。氏名は入れない**（個人情報）
- **満点は列見出しの `(数字)` から読む。** `問1_パイプモデル(10)` のように書く。
  設問構成が変わっても設定ファイルを触らずに済む
- **`小計`・`合計` で始まる列を持たない。** 派生値を持つと必ず本体とずれる（実際にずれた）
- **BOM付き UTF-8（`utf-8-sig`）で保存する。** Excel で文字化けさせないため
- **記号列（◎○△✗）には `(数字)` を付けない。** 付けると集計対象になる。
  判定の根拠を残したいときは点数列と別に置く
- **`欠` は欠席。分母からも外す**（提出機会が無かった回で減点しない）。
  **空欄は未採点**で、0点と区別して合計を出さずに警告する
- **1つのCSVは単一の粒度で持つ。** 総合列（`履修態度(10)`）と回別列（`0513-要点(3)`）を
  同居させると二重計上する。`grade_summary.py` が検出して停止する
- 判断の理由は `備考` 列へ日本語で残す。来年読み返したときに点数の根拠が分かる

### 回別列のキー

`{MMDD}-{観点}({満点})` の形（例 `0513-要点(3)`）。

**日付はセッションノート（`courses/{course_id}/sessions/YYYY-MM-DD_*.md`）から取る。**
答案の手書き日付は「どのセルがどの回か」の手がかりに留める。
学生は誤記する（2026年度に「6/3」を消して「6/11」と書いた例がある）。

## grading_config.json

Teams 入力欄の満点だけを書く。**換算の流儀を `_note` に残す**——科目によって2通りある。

```json
{
  "_note": "Teams側のExcelが重み付け換算するため、素点をそのまま入力する。ここの値は素点の満点と一致させ、換算を恒等にしておくこと",
  "exam": 70,
  "attitude": 10
}
```

| 流儀 | 例 | `grading_config.json` の値 |
|---|---|---|
| Teams の Excel が重み付けする | 造林学 | **素点の満点と一致させる**（換算が恒等になる） |
| 入力値がそのまま評価値 | 森林計画・政策論 | Teams 入力欄の満点そのもの |

担当者ごとに入力表の様式が違うため、**科目ごとに確認する**。キーは `exam` / `report` / `attitude`
で、無いキーは集計から外れる。

## grade_summary.py

```bash
python3 ~/work/projects/admin/scripts/grade_summary.py --course forest-planning --year 2026 --class U2
python3 ~/work/projects/admin/scripts/grade_summary.py --course silviculture --year 2026 --class U2 --csv
```

`scores_{exam,report,attitude}.csv` を読み、`grading_config.json` の満点へ換算して
小数第1位まで出す。`--csv` は Teams 貼り付け用。

- **丸めは `Decimal` の `ROUND_HALF_UP`。** 標準の `round()` は偶数丸めで 24.5 が 24 になる。
  成績に直結するため明示的に実装してある
- 換算式は `素点合計 ÷ 有効満点 × Teams満点`。`欠` の回は**分母からも外れる**
- 出力の `*` は、その系統に欠席分の除外があった印
- **学期途中でも動く。** 回別列がある分だけで計算するので、数回ごとに現在の点を学生へ返せる

## ルーブリックの帯

**採点を始める前に、必ず4点を確認する。** 2026年度に全部外して手戻りが出た。

1. **何を測るのか。** 知識か、記述の巧拙か、提案の実行可能性か。
   設問が挙げる要素（場所・作業・影響・理由など）は答案の構えを整える枠であって、
   配点の内訳とは限らない
2. **満点と、何点が標準か。** 「7割が標準」「7点が標準」のように基準点を先に置く。
   これを聞かずに採点すると全体が甘くなる
3. **同じ試験を別クラスでも使うか。** 使うなら片方のクラスの得点率だけで設問や配点を削らない。
   `grading_policy` の frontmatter `shared_with_class:` に記録する
4. **設問別配点か、全体を帯で見るか**

### 帯の書き方

標準点を中心に、上下を「何ができていれば」で定義する。造林学・森林生態学で使った形。

| 点 | 水準 |
|---:|---|
| 標準+2 | 標準+1 に加えて、トレードオフや限界にも踏み込んでいる |
| 標準+1 | 深い理解。概念が定義の引用でなく機能し、機構で説明している |
| 標準 | 求められた要素がひととおり書け、根拠が伴っている |
| 標準-1 | 誤用がある、または根拠が弱い |
| 標準-2 以下 | 設問の要求に大きな欠落がある |

**ルーブリックと点数を同時に提示しない。** 基準の妥当性と個別判定を同時に検証させることになる。
帯の承認を得てから採点に入る。

## grading_policy_{年}{クラス}.md

採点の正本。**来年この試験を使うときに最初に読む場所**なので、点数だけでなく判断の根拠を残す。

```markdown
---
shared_with_class: J1     # 同じ試験を使う別クラス。無ければ省略
---

# {年度} {科目}（{クラス}）採点方針

## 設問
## 何を測るか          ← 必須見出し
## 採点の帯（バンド）
## 判断の原則
## {年度}の結果
## 判断事例            ← 実際の答案を基準点として引用する
## 次回への申し送り
```

**判断事例に実物を引く。** 「◎ 十分に説明している」だけでは来年再現できない。
その年の答案を「これが9点」「これが7点」と埋め込むと基準が復元できる。

## 落とし穴（実際に踏んだもの）

- **クラス種別は学籍番号で検証する。** `registry.md` の誤記で森林生態学を U2 と判定し、
  フォルダを `2026U` で作ってしまった（正しくは J1）。U2 は `2511xxx`、J1 は `2621xxx`
- **`_meta.md` は9科目中3科目にしか無い。** `grade_summary.py` は `registry.md` へ
  フォールバックするが、course-qa の配布PDF出力先解決は `topics[].lecture_folder` を要求する
- **規準を学生に示す前に採点した点は成績に使わない。** 後出しの基準で成績を動かすことになる。
  `scores_attitude_reference.csv` に退避し、`scores_attitude.csv` には触らない
- **教材フォルダは git 管理外で undo が無い。** CSV を書き換える前に
  `{ファイル名}.bak-{YYYYMMDD}.csv` へ退避する
- **macOS のファイル名は NFD 正規化。** 日本語名のファイルを正規表現で拾うときは
  `unicodedata.normalize("NFC", name)` を挟む。半濁点付き（ペ・パ）が一致しない
