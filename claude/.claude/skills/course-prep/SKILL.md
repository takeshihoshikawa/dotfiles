あなたは、学期はじめの授業準備を、**抜けと重なりが無い状態で着手日まで落とす**ことを支援するアシスタントです。

## 目的

半期に1回しか回らない作業なので、毎回「どこに何が書いてあったか」を探し直すことになる。
2026年度後期（2026-09-11）に初めてこの形で計画し、次のことが分かった。

- **二重予約は目視では見落とす。** 11/10 に生産マネジメント実習I（1〜3限・演習林）と森林計画学 J1（3限）が
  どちらも星川担当で入っていた。カレンダーにも両方あったが、1月と3月に別々に登録されて気づかれていなかった
- **スクリプトの「0 件が変更対象」は「確認済み」を意味しない。** `topic_id` の無い回は飛ばされ、
  開けないデッキは一覧に出るだけだった（どちらも 2026-09-11 にスクリプト側で手当てした）
- 定型5件は名前だけのタスクで、**中身（どの回に何が要るか）はセッションノートと計画表に散らばっている**

## ステップ2: 機械で検査する

admin リポ（`~/work/projects/admin`）で実行する。

```bash
# 二重予約（同じ担当者・同じ日・時限が重なる）と、教室が未記入の担当回
python3 scripts/course_schedule_check.py --from 2026-10-01 --to 2027-02-28 --missing-room

# スライド表紙の日付（topic_id を持つ科目ごと。既定は dry-run）
python3 scripts/shift_keynote_dates.py --course silviculture --class J1 --year 2026
python3 scripts/shift_keynote_dates.py --course forest-planning --class J1 --year 2026
```

- **二重予約が出たら最優先で本人に返す。** 他の教員との入れ替えになるので、期限9/30の5件より先に動かす
- `shift_keynote_dates.py` は **`topic_id` の無い担当回を警告する**。出たら `_meta.md` の topics と
  突き合わせてセッションノートに足す（2026-09-11 に森林計画学 J1 の4回へ足した。J1 の題目は
  U2 と違う名前でも教材は共通：地球環境問題＝`climate-response`、森林GIS入門＝`spatial-planning`）
- 「開けなかったデッキ」は、スクリプトが Finder と同じ経路で一度開いてから再試行する。
  それでも残ったら、本人に Keynote で開いて保存し直してもらう

テンプレートは `~/vault/tasks.md` の `### 繰り返し（半期）`。名前しか無いので、中身はここで調べる。

| タスク | 対象になる回 | 手がかり |
|---|---|---|
| 技術職員への実習スケジュールの連絡 | 演習林・学外の回、チェーンソー実技の回 | セッションノートの `### 技術職員`（2026年度 11/17 選木は伏見さん・河合さん、旅費入力あり） |
| 授業資料の日付更新 | Keynote の表紙（ステップ2のスクリプト） | 生産マネジメントI の校外学習事前届（`5_チェーンソー/`・`9_先端技術/` の docx）は回ごとに作るので、ここでは扱わない |
| 公用車予約 | 演習林・林業現場の回 | 2026年度は 11/10・11/17・12/15・1/19・1/26。過去のタスクに「SDOパソコンで公用車の空き状況を確認する」がある |

| 外部講師依頼 | 生産マネジメントI の路網の回（天竜フォレスター） | `8_路網見学/派遣依頼文.docx`（学長名・教務課経由。年度・日付・人数を直す。2026-09 時点で本文が「令和5年度」のままだった）。講師料は `~/vault/notes/lecturer-fee-standard.md` |

## ステップ4: 着手日を決めて書く

1. テンプレートを `## teaching` へ実体化していなければ、`academic_ops.py task create` で作る（due は授業開始の前日ごろ）
2. 着手日は `python3 scripts/academic_ops.py task edit --id tsk-... --set scheduled=YYYY-MM-DD --apply` で入れる。
   **連休を先に確かめる**（2026年は 9/19〜9/23 が5連休だった）
3. 年間で一番忙しい 11月中旬〜12月中旬に始まる担当は、準備を10月へ前倒しする
   （2026年度は木材生産システムを10月第3週に置いた）
4. 決めたことは当日の日報に節を立てて残す（本人の決定・着手日の表・5件以外に学期はじめに来るもの）

**既知の問題**: `task create` は teaching セクションの末尾、つまりテンプレートのコードブロックの下に行を入れる
（2026-09-11 時点。inbox にタスクあり）。作ったら既存タスクの並びへ手で移し、
**移したあと `rg -c tsk-... ~/vault/tasks.md` が 1 になっているか数える**（移すつもりで足しただけになった前例がある）。
