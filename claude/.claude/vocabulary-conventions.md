# 技術語彙の規約

**日本語で技術文書を書くときの語彙の決め方**と、禁止と決めた語の表。
全プロジェクト共通。判断則の要約はグローバル `CLAUDE.md` の「## 出力スタイル」にあり、本ノートが正本。

## なぜ要るか

Claude が書いた文書に「周囲に合わせて書く」指示が掛かると、**自分の造語を読んで自分で強化する
再帰ループ**になる。`gate→門`・`floor→床`・`onset→発火` のように英単語に漢字1〜2字を当てる造語は、
読み手（本人を含む）が読めない。コードの識別子は英語（`onset_year`・`flags`・`anchor`・`gains`・`sweep`）
なので、造語は**文書だけにある翻訳層**であり、要らない。

## 5段の判断則

1. **英単語に漢字1〜2字を当てはめかけたら止まる。** gate→門、floor→床、wall→壁、sweep→掃引、
   onset→発火はすべてこの形。確認が要ると気づく前に訳してしまうのが失敗の起点なので、
   この動作自体をトリガーにする
2. 一般的な訳語・カタカナ表記が**あるか確認する**
3. **あっても読み手がその語だけで意味を取れないなら、具体語に開く。**
   訳語の実在は合格条件にならない（粒度は実在する訳語だが読みにくい）
4. どれも無ければ**英語のまま**。初出だけ `gate（ゲート）` と併記し、以降はカタカナ
5. **例外——その分野で定着した専門語、および文書内で定義して一貫使用する語は残す**

迷ったら**オライリー日本語版の技術書**を目安にする。

## 残す語（置換しない）

その分野で定着した専門語: **信号**（signal）・**較正**（calibration）・**盲検**（blinding。
医学統計の標準語で査読者に通じる）・**正本**・**偽陽性**・**律速**・**粗度**・**静穏**・
**白骨**・**連たん**（行政文書の引用時）。

林学・生態学の**層**（林冠層・下層植生・層構造）も正しい日本語。置き換えるのは
「ソフトウェアの層」「GISのレイヤ」の意味のものだけ。

地の文の述語も「〜を担う」「受理する」「〜に属する」のような状態記述に偏らせず、動く日本語にする。

## 検出の規則（機械検査を作るときの仕様）

- **語ごとに、造語側と正当語側の「どちらが開いているか」で規則を選ぶ。**
  一本化すると必ずどちらかを壊す。語の長さで分けない（相関しているだけ）:

  | どちらが開いているか | 規則 | 費用 | 語 |
  |---|---|---|---|
  | **造語側が開いている**（いくらでも作れる） | **部分一致 ＋ 少数の除外語** | 除外語は増えない | 発火・掃引・粒度・連担・悉皆・上界・下界・利得・**窓**・**床** |
  | **正当語側が開いている**（分野の語が今後も増える） | **境界つき完全一致** | 見逃した複合語を表に足す | **帯**・**門**・壁・旗・錨・篩 |

  **判定は数えれば付く。** 対象のリポで、その字を含む複合語の異なりを造語側と正当側に分けて数え、
  多い側が開いている。
- **境界つきにも偽陽性はある——動詞を見落とさない。** 「被害を**帯び**る」は前後が平仮名なので
  境界つきで当たる。**単漢字が動詞の語幹になる語**は、足すときに活用形を必ず確かめ、除外語に置く。
- **境界つきは、漢語の複合語には偽陽性を出さない。** 前後が非漢字で切れるトークンだけを
  見るので 専門・林床・温床・障壁・関門・帯域 は**除外リストなしで素通り**する。
  頭位置まで拾う正規化は `門屋`（地名）・`壁時計` を偽陽性にするため採らない。
  **見逃す複合語（`旗率`・`明度門`）は語として上の表に足す**
- **除外語は「その一致が正当な複合語の一部か」で効かせる。「同じ行・近くに除外語があるか」で
  判定しない。** 位置で判定すると、正当な複合語が近くにあるだけで本物の違反が消え、
  語順で答えが変わる（`林床と床効果を比べる` が0件、`床効果は林床でも起きる` は当たる）。
  見逃しは鳴らないので気づけない
- **部分一致の除外語**（正当な複合語）。**これで全部**——増えたら上の判定をやり直す合図:
  `窓関数` ／ `林床`（`林床侵入`・`林床露出` を覆う）・`温床`・`高床`
- **境界つきの除外語**: `帯び`（動詞「帯びる」）
- **件数だけで比べない。除外語の取りこぼしは「ノイズ」、表への追加漏れは「見逃し」で、
  値段が違う。** ノイズは毎回鳴って検査そのものを殺す（`doc_refs.py` と同じ）ので、
  **拮抗したら境界つきを採る**
- **除外は必要になってから1行足す。** 先回りしてリストを作らない。将来 `粒度分布`（土壌）・
  `情報利得`（ML）のような正当な複合語が出たら、その時に語レベルの除外として TOML に書く
- **追加行だけを見る。** 全文検査すると、直さないと決めた既存の行から数千件出て、
  毎回出るノイズは読まれなくなり検査そのものが死ぬ
- 範囲指定は `--since` ではなく**リポごとの baseline タグ**（`git diff vocab-baseline..HEAD`）。
  2台運用で rebase が頻繁なため、コミット日ベースだと書いていない行がウィンドウに再入する
- **`doc_refs.py` とは別スクリプトにする。** doc_refs は追記式の記録（worklog・ideas・decision-log）を
  既定で除外するが、語彙では逆で、**追記され続ける記録こそが対象**
- **本ファイル自身と `vocabulary-migration.md` は検査の対象外にする。** 禁止語を語として並べる
  場所なので、対象に入れると必ず鳴る。受け入れ基準が「無音」である以上、最初から除外パスに書く
- **コードの中の文字列は、コメントと三重引用符の中だけを見る。** 日本語の短い文字列は
  JSON の出力キー・DataFrame の列名になっていることがあり、別のスクリプトがその名前で
  読み戻す。置き換えると壊れるうえ、既にディスクにある結果ファイルとも食い違う。
  **恒久的な対象外**とする。分離は `tokenize` で機械的にできる
  ——COMMENT トークンと、三重引用符で始まる STRING トークンだけを対象にする
- **カタカナの長音は最長一致で見る。** `クラスター` は `ラスター` を含むので、
  素朴に部分一致を掛けると1語で2件鳴る
- **生成ブロックの中は見ない。代わりに正本の `.yaml` を見る。**
  `CLAUDE.md` の `**Concern**:` は `project-status.yaml` の描画なので、md を直しても
  `project render` で戻る。**直せない場所を指す指摘は、無いのと変わらない。**
  対象の拡張子に `.yaml`・`.yml` を入れ、md 側は `<!-- BEGIN GENERATED ... -->` 〜
  `<!-- END GENERATED ... -->` の行を飛ばす。両方を見ると同じ違反が2件になる
- **1回の実行で見るのは1リポだけ。呼ぶのは `close-project-session`。** 全リポを1か所から
  走査すると、その機械に clone があるリポしか見えず、他の機械で書いた文書が検査されないまま
  「全リポ無音」に見える。スクリプトを dotfiles に置くのも同じ理由——リポの外で、どの機械にも配られる
- 受け入れ基準: **参加しているリポで `--quiet` が無音**であること。鳴るなら仕様が間違っている
- モードは2つ。**enforce**（`close-project-session`・既知語・追加行のみ・無音が正常）と
  **candidates**（週次または随時・漢字トークンの頻度順で新しい造語を探す）。
  candidates は**毎日走らせない**

## 語彙の追加

candidates モードで候補を出す → 本人が選ぶ → **`vocabulary.toml` に1件足して `--render`**。TOML が唯一の入口。

## カバーしない範囲

**ファイルに落ちたものしか見ない。** ターミナルでの応答の語彙はグローバル `CLAUDE.md` だけが効き、
検査は掛からない。検査があるから安心、とはならない。
