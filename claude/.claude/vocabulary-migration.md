# 語彙の置換（pine-wilt-shizuoka / tea-abandonment-shizuoka）

2026-09-01 決定。docs に溜まったClaude造語を、**既にコードにある英字識別子へ合わせる**作業の指示書。

判断則と対応表は同じディレクトリの `vocabulary-conventions.md`。
**この文書は手順だけを持つ。**

**dotfiles に置く理由**: 置換作業はプロジェクトのリポジトリで行うので、admin リポを持たない機体
（gpu-remote など）からも読める必要がある。dotfiles は全機体に配られる。

## 背景

pine-wilt の docs は660コミット中629件がClaude共著で、12,000行が実質Claudeの文体だけで書かれていた。
そこへ「周囲に合わせて書く」指示が掛かるため、自分の造語を読んで自分で強化する再帰ループになっていた。
`gate→門`・`floor→床`・`onset→発火` のように、**英単語に漢字1〜2字を当てる**形で造語が量産された。

**コードの識別子は最初から英語だった**（`onset_year`・`detect_onset`・`flags`・`anchor`・`gains`・
`sweep`・`dissolve_touching`）。つまり造語は文書だけに存在する翻訳層で、訳語を新たに決める必要はない。

  文書側だけをそこへ合わせる

着手時の手順:

1. `git checkout -b vocab/replace`（main を汚さない）
2. **`outputs/presentations/` は除外する。** 過去の講演資料は当時の記録なので、恒久的に
   対象外にする判断もあり得る。着手時に決める
3. 単漢字8語（門・床・壁・窓・帯・旗・錨・篩）→ 境界つきで機械置換
4. 2字以上の語 → **複合語の訳を先に決めてから**置換（発火率→発生率、など）
5. `掃引`・`利得`・`帯` は1件ずつ読んで分ける
6. テストとデッキのビルドを通してから main へ

tea-abandonment-shizuoka は講演の制約が無いので先に着手してよい。

```bash
cd ~/work/projects/{リポ名}

for w in 発火 窓 旗 錨 連担 掃引 利得 帯; do
```

## やらないこと

- **コードの識別子は変えない。** `onset_year` 等はそのまま。文書側だけを合わせる
- **出力ファイル名・データのカラム名は変えない。** 再生成が必要になり、置換の範囲を超える
- **コードの中の文字列は、コメントと三重引用符の中だけを置き換える。** 日本語の短い文字列が
  JSON の出力キー・DataFrame の列名になっていて、別のスクリプトがその名前で読み戻していることがある。
  **後回しではなく恒久的な対象外**（2026-09-04 決定）。pine-wilt の実測で 260 件——
  `"発火数"`・`"対象の画素発火率"` が JSON キー、`温室旗率`・`旗_ha` が列名、
  `pixel_persistence_design.py` が `pixel_count_detector.py` の `"対照の発火率"` を読んでいた。
  分離は `tokenize` の COMMENT トークンと三重引用符の STRING トークンで機械的にできる
- **凍結済み・提出済みの文書は対象外。** 対象リポにそれがあれば先に除外リストを作る
- 表記揺れ（閾値/しきい値・頑健/ロバスト）はこの作業に含めない。別件
