# フェーズ: 申請書

公募研究計画書（科研費・学術変革・受託等）を書き、提出物を作るときの手順。
`proposals/` の位置づけとディレクトリ構造は `../research-project-conventions.md` が正本。

## 提出物のワークフロー

```
proposals/{YYYY}-{種別}/drafts/*.md
        ↓ pandoc --reference-doc=様式/template.docx
proposals/{YYYY}-{種別}/output/研究計画調書.docx
        ↓ コピー（節目・最終）
~/Documents/grant/{YYYYMMDD}_{種別}_{略称}/研究計画調書.docx
```

**markdown が真のソース。** Word は最終出力としてのみ生成する。共同研究者と Word で授受する
場合も、md → docx 変換を都度回す（Word 側で直接編集した内容を md へ戻す運用にしない）。

`output/` は gitignore 対象。git に残るのは `drafts/` の md と `figures/`・`refs/`・`budget/`。

## AI の使い分け（Claude / ChatGPT）

研究計画書では「自然で読みやすい文章」よりも**研究の芯が伝わること**を優先する。単一 AI に
依存するより、AI の特性差を役割分担で利用するほうが有効。

| 担い手 | 役割 |
|--------|------|
| **Claude 系** | 研究計画の内部構造を壊さず深化させる |
| **ChatGPT 系** | 査読者の認知コストを下げる |
| **人間** | 本当に重要な問いを保持する |

### Claude / Coding agent 系

論理構造の強化・長文脈維持・用語整合・セクション間整合・研究設計の深掘り。

向いている作業: 中心的問いの定義と仮説構造の整理 / 研究目的 ↔ 方法の対応づけ / 3柱・WP 構造の整理 /
予算 ↔ 計測 ↔ 研究目的の整合 / 用語統一 / 巨大文書の QA / 差別化軸の抽出。

> [!warning] 重くなりやすく、技術寄り・抽象度過多になりやすい
> 「正しいが読みにくい」方向へ行きやすいため、後段で編集工程が必要。

### ChatGPT 系

査読者視点・可読性改善・情報圧縮・インパクト整理・文章の温度感調整。

向いている作業: タイトル調整 / 見出し整理 / 冗長部分の削減 / 新規性の見せ方 / 査読者シミュレーション。

> [!warning] 一般論・既存カテゴリへ回帰させる傾向がある
> 「綺麗だが弱い文章」にしがち。研究固有の「変な強み」を消さないよう注意する。

### 3 フェーズを回す

1. **Phase A: 研究の芯を固定する**（Claude 系中心）
   本当に新しいものは何か / 絶対に失ってはいけない概念は何か / 差別化軸は何か を固定する。
   読みやすさ・文章美・キャッチーさは重視しない。**AI の自然化圧力に負けないこと。**
2. **Phase B: 査読者可読性を上げる**（ChatGPT 系中心）
   一読で理解できるか / 何が新しいか即座に伝わるか / 読み疲れしないか。圧縮・見出し改善・
   タイトル調整・語感調整。
3. **Phase C: 再度論理検証する**（Claude 系へ戻す）
   抽象化で本質が消えていないか / 差別化が弱まっていないか / 用語がブレていないか /
   方法と目的が対応しているか / タイトルと本文が一致しているか。

必要に応じて A → B → C を繰り返す。

### 特に注意すること

- **「読みやすい」は「強い研究」ではない。** 大型科研では、少しクセがあっても・密度が高くても
  研究の芯を保持したほうが強い場合がある
- **AI に新規性を定義させすぎない。** AI は既存カテゴリへ回帰させる傾向が強い。特に学際研究では
  「既存分野の境界にある違和感」こそが新規性であることが多く、これは人間が保持する必要がある
- Coding agent は**文書 QA に非常に強い**: 用語統一 / 図表整合 / budget–method consistency /
  セクション間の矛盾検出 / 「本文中で支えられていない主張」の検出

## 文献

引用文献はプロジェクト別の papis ライブラリ
（`proposals/{YYYY}-{種別}/refs/papis-lib`）で管理する。知識ベース `kb` から必要なものをコピーして
使う一方向フロー。運用は vault の `notes/papis.md`。

## 提出後

提出版を `~/Documents/grant/{YYYYMMDD}_{種別}_{略称}/` にコピーしてアーカイブする
（`init.sh add-archive` がディレクトリを作る）。

採択結果を待つあいだ並行作業が無いなら、vault のプロジェクトノートの `status` を `waiting` にする。
