# 論文投稿前チェック

投稿前の最終品質確認を AI エージェントに依頼するときの観点表。
研究内容・結果は変更させず、修正すべき点の抽出と提案のみを行わせる。

項目 1〜6 は原稿を読めば終わる。**項目 7・8 は原稿の外（文献の本文・解析スクリプト）に当たらないと終わらない**ため、
依頼前に入力を揃える。ここを省くと、通ったように見えて何も検証されていない結果になる。

---

## 依頼前チェック（人間が実施）

1. 派生物（表・図・本文に埋め込んだ数値）がパイプラインの最新出力と同期しているか確認する。
   プロジェクトの再生成コマンドを実行してから依頼する（例: `targets::tar_make()` → `quarto render`）。
   古い派生物を渡すと項目 8 が無意味になる。
2. 引用文献の要旨・本文 PDF を可能な限り文献ライブラリへ入れておく（項目 7 の精度は入力の充足度で決まる）。

---

## 入力

エージェントには以下を渡す。

- 原稿ソース（`.qmd` / `.tex` / `.docx`）とビルド済み PDF
- 投稿規定（URL または PDF）
- 文献ライブラリの場所（papis 等）— 項目 7 に必須。**リポジトリ外**なので原稿と一緒には渡らない
  （`~/dotfiles/claude/.claude/papis-conventions.md`）
- 解析スクリプトと出力（`results/` 等）— 項目 8 に必須
- （任意）Cover Letter

---

## チェック項目

### 1. 英文

文法 / 学術英語としての自然さ / 冗長表現 / 時制・冠詞・前置詞 / 用語・表記の一貫性

### 2. 投稿規定

Abstract 語数 / 本文長 / 図表数 / セクション構成 / 書式 / Supplementary Material

### 3. 論理構成

Introduction → Methods → Results → Discussion の流れ / 主張と結果の整合性 / 論理の飛躍 / 過剰な解釈

### 4. 図表

解像度 / フォントサイズ / 線幅 / 凡例 / 軸ラベル / 印刷サイズでの可読性

### 5. 相互参照

Figure / Table / Appendix / Supplementary Figure の番号が、本文中の参照と一致しているか

### 6. 引用文献（書誌の形式）

参考文献形式 / DOI / 重複 / 未引用文献 / 引用漏れ / 投稿規定との整合性

### 7. 引用と主張の対応（原典照合）

**項目 6 とは別物。書誌が完全に正しくても、その文献が主張を支えていないことがある。**
形式チェックだけを引用の点検と呼ばない。

#### 照合は 3 段階ある

| 段階 | 材料 | 検出できるもの |
|------|------|----------------|
| 1 | 題名 | 明らかな取り違え |
| 2 | 要旨 | 結論の向き違い・対比の取り違え |
| 3 | 本文 PDF | 条件・母集団・手法の限定、数値の出所 |

**題名照合だけでは下記の型 2 が通る。要旨照合は本文照合ではない。**
要旨を揃える費用対効果は高い（題名の段階で出なかった誤りが、要旨を補うと追加で出る）。
中心的な主張を支える文献は、段階 3 まで上げてから投稿する。

#### 検出すべき 2 つの型

1. **自分の結果を述べた文の末尾に他人の文献を置く。**
   文末の引用が、直前の自説まで支持しているように読める。**査読者が原著を当たる確率が最も高いのはこの型**であり、
   実測でも最頻。新しい文を書いたら必ず疑う。
2. **同じ向きの結論だと思って引いた文献が、実は逆向き・別の対比・あるいは自分の方法に反対する方法論文だった。**
   題名だけを見ていると通る。

> [!note] 実測（`nfi-understory-disturbance`、2026-07-28）
> 要旨を 30 → 56/60 件、本文 PDF を 6 → 30/60 件まで揃えて、**誤引用が通算 6 件**出た。
> うち **4 件が型 1**（自分の結果を述べた文の末尾に他人の文献）。残り 2 件は型 2 で、
> **題名照合では通り、要旨まで当たって初めて出た**。段階を上げた分だけ検出が増える。

#### 手順

引用が付いた文を 1 文ずつ、次の 3 つを並べて出させる。

- その文が主張していること
- 文献が実際に示していること（どの段階の材料で確認したか明記）
- 一致 / 不一致 / 過剰一般化 のいずれか

不一致は「引用を外す」「別の文献へ付け替える」「主張を弱める」のどれで直すかまで提案させる。

**カバレッジを必ず報告させる**（本文で照合できた件数 / 全件数）。
未照合の文献は、主張の中心度でランク付けして手当ての順に出させる。
「全件チェック済み」が段階 1 での全件を意味していないか確認する。

照合スクリプト（引用文と文献の要旨・本文を突き合わせる）を書かせてよい。
数字を含む文だけを見る数値照合は補助であって、この項目の代替にはならない。

### 8. 本文数値と再解析値の一致

本文・Abstract・Conclusion・キャプション・Supplement の数値が、**現在の**解析出力と一致しているか。
標本の再定義やパラメータ変更のあとは特に危ない。

- 一致確認は原稿を読み比べるのではなく、**スクリプトを実走させて**行う。
- 標本定義を変えたら、その標本を使う全スクリプトを走査し、旧定義が残っているものを洗い出す。
- 再現できなかった項目は「未検証」として明示的に残す。黙って通さない。

---

## 制約

以下は変更させない。問題がある場合は、変更せず提案のみさせる。

- 実験結果 / 数値 / 統計解析 / 図表の内容 / 結論

**存在を確認できない書誌を提案させない。** 不足している引用をそれらしく補う挙動が最も危険な失敗であり、
項目 7 の目的そのものを裏切る。挙げる文献はすべて文献ライブラリまたは DOI で実在を確認させる。

---

## 出力形式

重大度順（Critical → High → Medium → Low）に整理し、以下の表で出力する。

| Priority | Section | Issue | Recommendation | Reason |
|----------|---------|-------|---------------|--------|

項目 7・8 は表とは別に、照合できた件数 / 全件数を併記する。

最後に以下のいずれかで総合評価する。

- 投稿可能
- 軽微修正後に投稿可能
- 修正後に再チェック推奨
- 投稿前に大幅修正が必要
